# Round 0 · 需求与目标 + 系统雏形

> 定位：本项目「讨论迭代」流程的第 0 轮。本轮回答两个问题：我们要做什么、它大概长什么样。
> 状态：雏形草案，等待你的批注（方式见 §0）。

---

## 0. 本轮怎么批注

划词批注界面本身还没建（要先于本流程讨论清楚）。过渡办法二选一：

- 直接在对话里引用原文段落批注；
- 或直接编辑本文件，在对应段落下加 `> [批注] 你的话` 引用块。

## 1. 背景与要解决的问题

用 AI 做项目，最大的浪费不是写错代码，而是**开工前没对齐**：AI 自作主张选了方向，或双方各自以为理解了对方。本工具把"动手前对齐"变成一个固定流程：想法进、无歧义的总设计文档出。

## 2. 目标与成功判据

**目标一句话：** 把「构建前的讨论、细化、对齐」做成一个有可视化界面、可批注、可追溯、以总设计文档为终点的本地工具。

**成功判据（草案）：**

1. 产出的总设计文档中不存在未决问题，且通过了所选档位的自检；
2. 全程用户不因 AI 语言晦涩而卡住（划词即可要大白话）；
3. 每一轮讨论、每一条批注都落盘可查；
4. 未经用户明确授权，流程绝不进入"撰写总设计文档"步骤。

## 3. 全流程：五个阶段、三道门

| # | 阶段 | 输入 | 产出 | 通过条件（门） |
|---|------|------|------|----------------|
| 1 | 需求与目标 | 一句话想法（或空白） | 需求/目标陈述 | 用户认可 |
| 2 | 雏形 | 目标陈述 | 雏形文档 | **G1**：用户认可雏形方向 |
| 2.5 | （可选）发散模式 | 没想法 | 候选方向 → 雏形 | 同 G1 |
| 3 | N 轮迭代收敛 | 雏形 | 每轮一份 `round-N.md` | **G2**：该轮批注全部被回应 + 未决清单为空 |
| 4 | 撰写总设计文档 | G3 授权 | `DESIGN.md` | **G3**：用户**明确授权**（默认拒绝） |
| 5 | 自检（宽松/严格） | `DESIGN.md` | 修订版 + 核查报告 | 无错误（严格档：循环直至零问题） |

可选后续：基于总设计文档追加分模块文档。**总设计文档是唯一权威**，分模块文档只做拆分细化，不得与它冲突；模块怎么划分由讨论自行判断。

流程终点 = 总设计文档收敛。代码实现不在本工具职责内。

## 4. 雏形：这个系统长什么样

**形态：** 单机单用户的本地 Web 应用。浏览器打开，左边文档、右边讨论与批注。后端很薄：管流程状态、存文档、调 AI。

**与 AI 的关系（候选架构，开放问题 1）：**

- **方案 A（推荐）：** 后端封装 Claude Code 无头模式（子进程调用 `claude -p`），AI 拥有完整智能体能力（能读写文档磁盘文件、执行流程）。工具本体只做界面与流程编排。
- **方案 B：** 做成 Claude Code 的插件/skill 集合 + 本地静态批注页。流程逻辑散在 skill 里，前端更薄，但交互闭环差些（关键词批注要回终端处理）。

**数据落盘（草案）：**

```
<项目目录>/
  docs/round-N.md            # 每轮一份讨论文档
  docs/round-N.annotations.json  # 每轮批注，与文档并存
  DESIGN.md                  # 最终总设计文档（唯一权威）
```

**当前假设（可否决）：**

- [假设] 单机、单人、本地运行，不考虑多项目并行与多人协作；
- [假设] 讨论文档以中文为主、纯 Markdown 存储，版本间可直接 diff；
- [假设] 中途关掉应用/重启电脑后回来，状态完整（都靠磁盘文件恢复）。

## 5. 两大易用性机制

### 5.1 语言红线（prompt 约束，草案原文）

> 输出必须简洁、精准，不用晦涩词语。但解释必须清晰、完整——简洁不等于省略，不许因追求简短而含糊带过。未定义的术语不用；必须用术语时，先用一句大白话定义。一次讲一个小点，讲透。

此约束注入流程的每个阶段（讨论、发散、写文档、自检），不只在某一环。

### 5.2 划词批注（界面核心交互）

```
┌─ 文档区（左/主） ──────────────┬─ 侧栏（右） ────────┐
│  ......正文段落......          │ 讨论/批注流          │
│  ┌被选中的一段话┐ ← 划词弹菜单  │  · 批注#1 及 AI 回复 │
│  └─────────────┘  [批注][大白话]│  · 批注#2 处理中     │
│  ......后续正文......          │  · 状态: 本轮待处理 2 │
└───────────────────────────────┴─────────────────────┘
```

- 划词 → 弹小菜单 →「批注」或「用大白话讲这段」；
- 批注与被选原文绑定存档，AI 回复附在旁边；已解决批注变灰但不删除；
- 每轮"本轮批注未处理数"显式可见，全部处理完毕该轮才可标记结束。

## 6. 发散机制（阶段 2.5，没想法时）

做成一个可单独调用的"发散模式"（机制/skill 形态，随取随用）：

1. **输入：** 只言片语或纯空白；
2. **多视角风暴：** 换 N 个视角（如：解决谁的什么痛点 / 最省事的版本 / 最贵的版本 / 那些没人做但该有人做的）各出 2~3 个方向，鼓励离谱；
3. **收敛：** 汇成 3~5 个候选方向，每个一句话说明 + 一句"为什么值得做"；
4. **出口：** 用户挑一个（或让 AI 挑），深化成雏形 → 回到主干流程。

## 7. N 轮收敛的驱动机制

AI 维护一份**未决问题清单（ledger）**，每轮固定四步：

1. 逐条回应上轮全部批注（含大白话请求）；
2. 更新文档（本轮版次），已定决策标注"已对齐"；
3. 追问新的更深层细节问题，进入清单；
4. 文末公开当前未决清单。

**收敛判据：** 未决清单为空，且连续一轮无新问题、无新批注 → AI 请求授权（G3）。不满足则开启下一轮。

## 8. 授权与自检

**授权（G3）：** 默认拒绝。形式草案：界面按钮「授权撰写总设计文档」+ 输入确认词二次确认，无法误触；终端模式下需用户明确说出/写出授权。

**自检档位（用户选择）：**

| 档位 | 行为 |
|------|------|
| 宽松 | 做一次全面核查，修复发现的问题，出核查报告 |
| 严格 | 循环核查，直至连续一轮零问题才停（报告每轮留存） |

核查维度（草案）：内部一致性、与全部批注的符合度、决策无歧义、可实施性、覆盖所有已对齐结论。

## 9. 范围边界

- **内：** 讨论流程（五阶段）、划词批注界面、发散机制、文档与批注落盘体系、自检机制、授权门。
- **外：** 写代码实施、多项目并行、多人协作、云端部署、批注以外的编辑能力。
- 分模块文档 = 可选后续，非默认产出。
