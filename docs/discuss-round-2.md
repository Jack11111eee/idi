## 3. Q1 深化:怎么做到「看得见 + 可控」

### 3.1 关切拆解

「无法看见输出」其实是两个问题:①不知道 AI 在干什么(不可见);②中途觉得不对无法介入(不可控)。这两点**都不需要放弃无头架构**:

### 3.2 方案 H1:无头 + 事件直播(推荐)

`claude` 无头模式的输出本身就是一串**事件流**——AI 说的每句话、每次读文件、每次写文件,都是一个逐行实时输出的 JSON 事件。后端把这串事件原样转发给浏览器,渲染成「AI 工作面板」:

```
┌─ 文档区(左/主) ────────┬─ 侧栏(右) ────────────┐
│  ...正文... 划词→批注   │ ◉ 批注流               │
│  (高亮 = 有批注)       │   #3 已回应 · #4 待处理 │
│                        │ ◉ AI 工作面板(直播)     │
│                        │   ▸ 读取 round-1   ✓   │
│                        │   ▸ 回应批注#3 ...      │
│                        │   ▸ 写 round-2 ...      │
│                        │ [中止]   [处理本轮批注] │
└────────────────────────┴────────────────────────┘
```

- **可见:** 从你点「处理本轮批注」起,AI 读什么、写什么、正在回什么都逐条直播。不是黑箱等几分钟蹦结果,而是全程看着它干活。
- **可控:**
  - **中止按钮**——不对劲随时杀掉进程;文件驱动设计(D 系列)保证杀掉无损;
  - **权限门**——AI 写 `docs/` 内文件自动放行;要动项目外文件或执行命令,浏览器弹窗要你点「同意」。
- **实现路线:** Python 端用官方 Claude Agent SDK(进程内拿到结构化事件流+权限回调);底层同样是 claude CLI,使用前提不变(本机已装并登录)。若 SDK 有不趁手处,退回直接子进程跑 `claude -p --output-format stream-json`,界面契约完全相同。

### 3.3 方案 H2:另开一个看得见的终端窗口(不推荐)

后端弹出真 Terminal 窗口跑 claude,你在里面直接对话;浏览器只当文档阅读器+批注板。

**问题:** 这实质上等于 round-0 里你否掉的**架构 B**——讨论发生在终端、批注发生在浏览器,同一场讨论的两个半边互相够不着:你划的批注不会自己走进终端对话,「批注→回应」的闭环要靠人工搬运。

**说明:** 如果你其实想要的形态就是「在终端里直接跟 claude 聊」,那要推翻的不是 Q1 而是 D-01,也可以——但那是另一个决定,请直说。

### 3.4 生成中途插话(暂不做)

技术上支持在 AI 工作中途插入新消息(双向流)。会打断批量处理的收敛节奏,列入 v2 再议。

## 4. 本轮新问题

### Q-K2:工作面板的展示深度

- **A(推荐)全部原始事件:**每条工具调用与结果都展示,可折叠收起。透明优先,且兼作调试出口。
- **B 精简摘要:**只展示「正在回应批注#3」这类概括。界面安静,但退回半黑箱。

### Q-K3:「大白话」问答要不要落盘

**提议:**落盘,与批注存同一处,但样式区分(灰色斜体)。理由:①它也是讨论资产——事后能查「我当时哪里没听懂」;②**不计入未决问题清单**,不驱动轮次推进(它只是消歧,不产生新决定)。

### Q-K4:按「中止」后,半成品文档怎么办

- **A(推荐)简单自愈:**约定 AI 只在收尾一步写出 `discuss-round-N.md`;中断通常不会留下文件;偶尔写了一半→下次重跑同轮直接覆盖,自愈。无额外机制。
- **B 整洁版:**AI 先写 `.draft` 名,后端确认完整后改名正式名。多一层约定,略复杂。
