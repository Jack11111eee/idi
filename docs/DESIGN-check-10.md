## 二、问题清单

**P2-1|§7.3② vs §8.2:「继续自检」常驻与隐藏两说(v1.9 新暴露)**
- 位置:§7.3②("自检进行中状态下界面**常驻**「继续自检」按钮")vs §8.2("暂停期与裁决已落盘期间**隐藏「继续自检」**、只呈现「继续修复」")
- 描述:暂停态按 §7.4 行 6 落"自检进行中",处在 §7.3② "常驻"的字面辖域内。两节对同一按钮给出常驻/隐藏相反指令,§7.3② 既无"见 §8.2"交叉引用,也无优先级声明。按 §7.3② 字面实现,暂停期两按钮并列,check-9 #1 要防的"误点「继续自检」→ 重跑覆盖当轮报告 → 销毁裁决唯一载体"重新可达。本文先例(§7.4、§5.4 两表头均显式声明"自上而下首条命中")表明静默的"特例优先"不被认为足够。
- 建议修法:§7.3② 改为"界面常驻「继续自检」按钮(§8.2 暂停态与裁决落盘期隐藏)"。

**P2-2|§8.2 追加内容 vs §6.4:暂停态签名无机器识别文法,且与报告末行声明冲突**
- 位置:§8.2("后端即把问题本身追加落盘到当轮核查报告末尾……重启后可重新展示")vs §6.4("其余轮末行为 FIX 或 BLOCK 及计数")
- 描述:①"重启后可重新展示"与"隐藏继续自检"都要求工具从磁盘机械识别"报告尾部存在待裁决的问题"——但追加内容无任何文法(起始标记、与结论行的位置关系),而 §6.4 的报告文法只承认结论行为末行,追加之后该声明字面失真;实现者只能自行发明"结论行之后的尾部内容 = 待裁决"之类规则。②无防重规则:暂停期「继续修复」即已呈现,裁决尚未给出时误点会重跑修复、再次触发抛问,问题被重复追加,识别与展示进一步混乱。
- 建议修法:为追加内容钉死最小文法与幂等:结论行之后允许后端追加标记行(如 `> 待裁决:` / `> 裁决:`),工具以标记存在判暂停态;后端仅当标记不存在时追加(幂等)。§6.4 末行声明同步补"其后可由后端追加裁决记录"。

**P2-3|§8.2:严格档轮与轮之间的正常推进无入口定义(前九轮漏检)**
- 位置:§8.2("严格——循环核查,直至某一轮零问题……才停")与 §7.3②(v1.9 后「继续自检」仅限中断恢复)
- 描述:全文每个推进节点都有钉死的触发物(G1 按钮、「处理本轮批注」、「继续撰写」、「继续修复」、档位弹选),唯独"第 N 轮修复正常完成后、第 N+1 轮核查由谁/什么触发"只有"循环/链"一词隐含。v1.9 又把「继续自检」限定为"仅用于报告未完整的意外中断",明确排除它承担正常推进;按本工具"各步均显式触发"的自身惯例实现,此处无入口(循环停摆,或被迫误用「继续自检」重跑覆盖 N 号报告,违背"严格每轮 1 份")。
- 建议修法:补一句"严格档每轮修复正常完成后,由后端自动开启下一轮核查(宽松档即由修复者追加 PASS 收尾)"。
