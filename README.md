# 交互式讨论迭代系统(Interactive Discussion Iteration)

[English](README.en.md) | 中文

一个**本地运行**的 Web 工具,把「AI 项目开工前的讨论、细化、对齐」做成固定流程:

> **想法进,无歧义的总设计文档出。**

单机、单人、本地运行,讨论文档以中文为主。

---

## 它解决什么问题

用 AI 做项目,最大的浪费不是写错代码,而是**开工前没对齐**:AI 自作主张选了方向,或者双方各自以为理解了对方。

本工具把「动手前对齐」变成一个有可视化界面、可批注、可追溯、以总设计文档为终点的流程。它只管讨论到设计文档为止——**写代码实施不在本工具职责范围内**。

## 核心机制

### 五阶段、三道门

| # | 阶段 | 产出 | 通过条件(门) |
|---|------|------|----------------|
| 1 | 需求与目标 | 需求/目标陈述 | 阶段 1-2 为一段连续会话,唯一正式出口是 G1 |
| 2 | 雏形 | `docs/draft.md` | **G1**:用户点「认可雏形」 |
| 2.5 | 发散模式(可选) | 候选方向 → 雏形 | 同 G1 |
| 3 | N 轮迭代收敛 | 每轮一份 `discuss-round-N.md` | **G2**(每轮):该轮批注全部被回应;阶段出口 = 未决清单清零 + 维度表全绿 |
| 4 | 撰写总设计文档 | `DESIGN.md` | **G3**:用户**明确授权**(默认拒绝) |
| 5 | 自检(宽松/严格) | 修订版 + 核查报告 | 宽松档:核查+修复+报告即完成;严格档:连续一轮零问题 |

**G3 是全流程的核心约束:** 未经用户明确授权,流程绝不进入「撰写总设计文档」步骤。授权按钮的点亮条件是四处机械校验全部通过(无待处理批注、未决清单清零、覆盖维度表全绿、AI 申请标记为「是」),点击后还需输入确认词「确认授权」二次确认。

### 关键设计

- **单一界面走完五阶段** —— 左侧文档区 + 右侧批注流与 AI 工作面板,不设独立页面;
- **双轨批注** —— 划词「用大白话讲这段」数秒内即时回答(不计入收敛进度);实质批注攒够后点「处理本轮批注」,AI 一次性统一回应;
- **轮次冻结** —— 一轮文档在下一轮产生后即只读,批注永远挂在它诞生的那轮文档上,不存在批注漂移;
- **收敛判据客观化** —— 固定七个覆盖维度,全绿 AI 才有资格申请授权;
- **权限门** —— 读项目内文件、写 `docs/` 内与 `DESIGN.md.tmp` 自动放行;`DESIGN.md` 直写与 `AUTHORIZATION.md` 写入仅后端可做(AI 视为越权);其余读写项目外、执行任何命令,都需你在界面点同意;
- **文件即状态** —— 工具不维护独立流程状态,一切由磁盘现状推导。重启、崩溃、关机后回来打开,状态完整;
- **事件直播** —— AI 说的每句话、每次读文件写文件,实时推送到工作面板,不是黑箱等结果。

## 快速开始

### 前提

- 本机已安装 [claude CLI](https://docs.claude.com/en/docs/claude-code) 并已登录(启动时会自检);
- Python 3(开发环境为 3.13)。

### 运行

```bash
./run.sh
```

脚本会自举虚拟环境(不存在则创建 `.venv` 并安装依赖),然后启动服务器:

```
http://127.0.0.1:8765
```

打开浏览器访问该地址即可。

### 使用流程

1. 在首页输入框填入要讨论的**项目目录绝对路径**(讨论文档会写到该目录下的 `docs/`);
2. 没想法就点「让 AI 发散出候选方向」,有想法就直接在会话流里聊;
3. 雏形草稿成型后点「认可雏形」(G1),进入轮次迭代;
4. 逐轮讨论:划词提问或批注,点「处理本轮批注」推进下一轮;
5. 未决清单清零、维度表全绿后,AI 申请授权——你输入「确认授权」,AI 撰写总设计文档;
6. 选择自检档位(宽松/严格),核查通过后界面提示「使命完成」,流程结束,进入只读归档态。

## 项目结构

```
backend/          # Python + FastAPI 后端
  main.py         #   应用与路由(会话/SSE/中止/权限)
  session.py      #   会话与流程编排
  ai_caller.py    #   AI 调用双路线(SDK 首选 / claude CLI 子进程兜底)
  grammar.py      #   §6.4 机器可解析文法
  prompts.py      #   各阶段提示词
  tests/          #   pytest 测试
frontend/         # 原生 HTML/JS + markdown 渲染库
  index.html
  app.js
  style.css
docs/             # 本项目自身的讨论过程与核查报告(discuss-round-*.md / DESIGN-check-*.md)
DESIGN.md         # 本项目自身的总设计文档——唯一权威设计文档
run.sh            # 一键启动脚本
config.json       # 运行配置
```

## 配置

仓库根 `config.json` 是唯一配置来源:

| 字段 | 取值 | 说明 |
|------|------|------|
| `ai_caller` | `"sdk"` / `"subprocess"` | AI 调用路线。`sdk` = Claude Agent SDK(首选);`subprocess` = `claude -p --output-format stream-json` 子进程兜底。两条路线界面契约一致,可随时替换 |
| `ai_model` | 模型名或 `null` | 指定 AI 模型;`null` 用 CLI 默认 |

## 文档

- **`DESIGN.md`** —— 本项目的唯一权威设计文档(v1.13 收口版)。其他一切描述与之冲突时,以它为准;
- `docs/discuss-round-0~4.md` —— 本项目自身的讨论过程;
- `docs/DESIGN-check-1~14.md` —— 本项目自身的自检核查报告;
- `.planning/` —— 实施辅助视图(路线图、需求、阶段验证记录),不构成权威。
