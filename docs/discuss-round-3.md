## 4. 三张草图收口

### 4.1 发散模式(→ Q8)

- **入口:** 仅限阶段 1-2(雏形诞生前)。新建项目时选「没想法」进入;一旦雏形存在,发散模式关闭——后续分歧一律走批注,不开倒车。
- **实现:** 内置一段「发散指令模板」(专用提示词,等价于随工具内置的 skill,对应你最初"机制或类似 skill"的设想),跑在 D-10 同一条调用链路上,过程照常直播到工作面板。
- **产物:** `docs/brainstorm.md`。草稿文件,可反复覆盖,不编号、不冻结、不进未决清单。
- **出口:** 你从候选方向里挑一个(或委托 AI 挑),深化为雏形,回到主干。

### 4.2 授权形态(→ Q9)

- **资格门槛:** 未决清单为空 + 维度表全绿。渲染依据:每轮文档固定包含「维度表」小节和文末「申请授权:是/否」标记,**工具解析这两处**来点亮按钮,不信 AI 自报"我收敛了"。
- **通过形式:** 点亮「授权撰写总设计文档」按钮 → 弹确认框 → 输入确认词「确认授权」二次确认,防误触。
- **拒绝:** 就是一条普通批注(写明还差什么),继续下一轮。

### 4.3 自检机制(→ Q9 同题确认)

- **档位:** DESIGN.md 初稿写完即在界面弹选项:宽松 / 严格。
- **执行者:** 全新的无头调用,不带讨论上下文、只读磁盘资料——干净的眼睛最容易看出问题。
- **核查五维:** 内部一致性 / 历史批注符合度 / 决策无歧义 / 可实施性 / 结论覆盖(13 条决策无一遗漏)。
- **产出:** `docs/DESIGN-check-N.md`(宽松 1 份;严格每轮一份)+ 修订后的 DESIGN.md。
- **停止条件:** 宽松 = 修一轮出报告即止;严格 = 循环直至连续一轮零问题。
- **终点:** 核查通过,界面弹「使命完成」提示,流程正式结束(实施不在范围内)。

## 5. 批注数据结构(→ Q10)

文件:`docs/discuss-round-N.annotations.json`,与轮次文档并存:

```json
{
  "round": 3,
  "items": [
    {
      "id": "a3-01",
      "quote": "被划选的原文(精确文本)",
      "before": "原文前 40 字(选中文本重复出现时辅助定位)",
      "type": "comment | plain",
      "note": "你写的话",
      "status": "pending | answered",
      "answer": "AI 的回应(plain 即时答;comment 批量回应)",
      "created_at": "2026-09-08T01:02:03+08:00"
    }
  ]
}
```

- `type: plain` = 大白话问答(D-05/D-12);`comment` = 实质批注,进未决清单驱动收敛。
- 定位靠精确文本匹配;轮次冻结(D-07)保证被批注的文本永不变化,不需要更复杂的算法。

## 6. 启动前提与恢复规则(→ Q11)

- **前提:** 本机已装 claude CLI 并登录;应用启动时自检,不满足就给出指引(只挡第一次)。
- **启动流程:** 打开应用 → 选择或输入项目目录 → 进入单界面。
- **恢复规则(文件即状态):**
  - 所选目录无 `docs/` → 新讨论;有 → 自动恢复,当前轮 = 最大编号 N;
  - 服务器崩溃/被杀 → AI 子进程随之终止,半成品文件按 D-13 重跑覆盖自愈;
  - 批处理进行中关掉浏览器 → 服务端照常跑完并落盘,直播错过就错过(结果一定在)。直播不做回放,避免为一屏废视流建档案系统。
